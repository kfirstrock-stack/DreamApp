# DreamApp

Живая история мест в фотографиях: карта + шкала времени до минуты.

## Запуск на телефоне

```
cd ~/project/DreamApp
cp .env.test.example .env.local
npx expo start
```

`.env.local` говорит приложению, к какой базе подключаться. Файл выше — тестовая база, не прод.

Затем откройте DreamApp в **Expo Go** на телефоне (карточка в списке серверов или QR-код камерой).

- Если добавились картинки, шрифты или что-то «не подхватилось» — запускайте с очисткой кэша: `npx expo start -c`
- Чтобы применить изменения без перезапуска сервера: встряхните телефон → **Reload**
- Если Expo Go пишет «not signed in to Expo CLI»: `npx expo login`

## Стек

Expo (React Native) · Expo Router · Reanimated · Supabase (PostGIS)

## Демо-данные

Демо-авторы и снимки в боевой базе помечены `is_demo = true`. Картинки лежат в `assets/demo/` — это фото Исаакиевской площади и собора с Wikimedia Commons. Кто снял и какая лицензия: `assets/demo/ATTRIBUTIONS.md`. Перед релизом демо убрать.

## База данных (Supabase)

Две базы. Приложение берёт адрес и ключ только из `EXPO_PUBLIC_SUPABASE_URL` и `EXPO_PUBLIC_SUPABASE_KEY`. В коде запасного ключа нет, поэтому тестовая сборка не откроет прод, если переменные забыли.

| | Тест | Прод |
| --- | --- | --- |
| Проект | `wmyinjftktwvjvcvclph` | `xxuzjmjkgfjxmdqehvap` (`faces-and-places`, eu-central-1) |
| Локально | `.env.test.example` → `.env.local` | `.env.production.example` → `.env.local` |
| Сборка EAS | профили `development` и `preview` | профиль `production` |

- `eas.json` — профили сборки. `preview` ставится внутренней установкой и смотрит в тест. `production` — сборка для магазина и смотрит в прод.
- В репозитории только публичные anon / publishable ключи. `service_role` и пароль базы не коммитить.
- `supabase/schema.sql` — справочная копия схемы прода: таблицы, RLS, функции, бакеты `photos` и `photos-private`. Это не миграция. На живую базу не запускать как есть.
- Бэкап данных прода делается вручную и хранится вне репозитория.

Бесплатный проект засыпает без запросов. GitHub Actions (`.github/workflows/supabase-keepalive.yml`) раз в два дня делает только чтение: одна строка из `photos` и проверка входа, для теста и для прода. Запись в базу не идёт. Если задача красная — проект, скорее всего, на паузе, его включают в панели Supabase.

Раз в месяц та же задача дописывает `.github/keepalive.txt`. Иначе GitHub выключает расписание через 60 дней без коммитов в репозиторий.

Проверить руками: `npm run keepalive`. В выводе каждый запрос должен быть `HTTP 2xx`.
